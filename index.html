Section 01

研究背景：AI 法律顧問的困境

想像有一個工廠發生了工安意外：一名作業員在距地面3公尺的施工架上作業時失足墜落，造成骨折。現在你的任務是：找出雇主違反了哪些《職業安全衛生法》條文。

這個任務對人類律師而言需要大量的法規知識與推論能力。研究者希望讓大型語言模型（LLM）來扮演這個「職安法務顧問」的角色：輸入事故情境描述，輸出具體涉及的法律條文與違規理由。

三個核心痛點

在前期研究中，直接使用 LLM 搭配 RAG（Retrieval-Augmented Generation，檢索增強生成）的方法遇到了三個嚴重問題：

痛點 1 — 語意異質性（Semantic Heterogeneity）

同一件事可以用很多種說法描述：「墜落」= 「失足」= 「跌下」；「施工架」= 「高3公尺處」= 「高處作業平台」。向量相似度搜尋容易誤判：這些說法在語意上可以是相似的，向量距離也可能是相似的，但在職業安全災害中，施工架有施工架的規定、高度也有高度的規定、高處作業平台也有高處作業平台的規定：單純只有根據向量相似度可能無法準確找到最關鍵的職業安全法規。

痛點 2 — 檢索-生成鴻溝（Retrieval-Generation Gap）

就算在檢索法規的任務上可以順利，但最終任務是生成，而從檢索到生成的過程中要如何維持關鍵依據不被適配器投影放大後模糊掉是個挑戰。

痛點 3 — 頻率偏差與通用建議陷阱（Frequency Bias）

這跟前期研究所建立的 369 份職業安全災害案例資料集本身的長尾分布有關，也就是「雇主應訂定職業安全衛生管理規範」、「主應加強安全教育訓練」這樣的條文因為出現頻率高，幾乎可以適用於每一種職災案例。LLM 因為預訓練時接觸過太多類似句子，會偏向輸出這類安全牌答案，卻回避了真正重要、案例稀少但精確的法條。

研究核心思路

強迫 AI 開口說話前，先做幾何體積的計算 (?)。不讓模型依賴文字頻率自由發揮，而是用數學嚴格的幾何運算來約束它能說什麼、不能說什麼。

Section 02

核心概念：知識圖譜與圖嵌入

什麼是知識圖譜（Knowledge Graph）？

直觀類比

你在 Google 搜尋「全面啟動導演的妻子是誰」，Google 知道答案不需要全文比對——因為它的內部有一張「知識圖譜」，記錄著：（Christopher Nolan, 導演, Inception） 和 （Christopher Nolan, 已婚, Emma Thomas）。這張圖就是一個巨大的「事實關係網路」。

知識圖譜的基本單位是三元組（Triplet）：

Definition (head, relation, tail)
-- 例：
(墜落事件_A, HAS_CAUSE, 未設安全網)
(未設安全網, LEADS_TO, 違規項目_B)
(違規項目_B, VIOLATES, 職安法第18條)

本研究的職安知識圖譜包含四種節點類型：職災事件（Incident）、直接原因（Cause_Direct）、違規項目（Violation）、法規條文（Regulation）；三種邊的類型：HAS_CAUSE、LEADS_TO、VIOLATES_LAW。

圖1：職安知識圖譜的節點類型與關係。四種節點、三種關係形成一張異質有向圖（Heterogeneous Directed Graph）。

什麼是圖嵌入（Graph Embedding）？

圖嵌入的目標是：把每一個節點轉換成一個多維向量，讓圖譜中關係越密切的節點，其向量在數學空間中的距離也越近。

就像 Word2Vec 的邏輯

你可能聽過 word embedding：「國王 - 男人 + 女人 ≈ 女王」。圖嵌入的邏輯類似——我們希望「墜落事件」和「高處作業違規法規」在向量空間中彼此接近，因為它們在圖譜中有強連結。

傳統的圖嵌入方法（如 TransE）把每個節點表示成空間中的一個點。這對普通知識庫夠用，但對法律推論有根本問題——我們稍後在 BoxE 那節詳細解釋。

Section 03

核心概念：RGAT 關係圖注意力網路

GNN（Graph Neural Network，圖神經網路）的核心思想是訊息傳遞（Message Passing）：每個節點更新自身特徵時，會聚合其鄰居的特徵。就像課堂討論：你的想法受到周圍同學的影響。

為什麼需要「Relational」？

傳統 GCN（Graph Convolutional Network）只知道兩個節點之間「有邊（1）」或「沒有邊（0）」，所有的邊共用同一個學習矩陣 W，也就是說，GCN 中只考慮一個種類的邊。

問題在於：在職安知識圖譜裡，邊是有種類的。如果我們不區分，模型會同時認同：

  • (合理)「未正確架設施工架而從施工架落下」(違規項目)[VIOLATES] (違反)施工架相關規範 (法律)
  • (不合理)「未正確架設施工架從施工架落下」(違規項目)[LEADS_TO] (違反)施工架相關規範 (法律)
  • (合理)「作業員未正確架設施工架」(造成職災的原因)[LEADS_TO] (造成)「未正確架設施工架而從施工架落下」(違規項目)
  • * 備註：現在這裡是比較「同樣是 *違規項目 -> [邊] -> *法律」，但是 [邊] 種類不同的情況；如果是考慮「同一種邊」但「方向不正確」(或節點類型不同)，比如「*違規項目 -> [違反] *法律」跟「*法律 -> [違反] -> *違規項目」是否等價，這部分要在後面講解幾何空間嵌入的段落才會被解決。

這顯然語意不通，卻是傳統 GCN 無法分辨的。

RGAT 的解法：替每一種關係 r 配置一個專屬的投影矩陣 W_r，讓不同類型的關係把特徵投影到不同的特徵子空間。

RGAT Message -- 傳統 GCN（所有關係共用同一個 W）：
h_i ← σ(W · Σ h_j) ← 不區分關係種類

-- RGAT（每種關係各自投影）：
h_i ← σ(Σ_r Σ_{j∈N_i^r} α_ij^r · W_r · h_j)
↑ ↑
注意力權重 關係專屬投影矩陣

為什麼還需要「Attention」？

直觀類比：找同學討論

假設你要準備期末考，班上有10個同學都可以幫你。你不會把所有人的意見平均加總——你會找其中最強的那一兩個，給他們更高的權重，再取加權平均。這就是 Attention 機制的本質：給予不同鄰居不同的參考價值（注意力權重）。

注意力權重 α_ij^r 是學習出來的：模型透過訓練，自動學會哪些鄰居在特定關係下更重要。這讓訊息傳遞更有針對性，不至於把所有資訊一視同仁地模糊平均。

RGAT 在本研究的作用

RGAT 負責對整張職安知識圖譜做特徵學習，讓每個節點（職災事件、法規條文…）都得到一個高維向量表示，且此向量考慮了圖譜的結構資訊、關係的語意、以及鄰居的重要性。這些向量隨後被送入 BoxE 做幾何建模。

Section 04

核心概念：BoxE 幾何空間嵌入

這是整個研究中最關鍵的幾何直覺，請仔細理解這一節。

傳統點嵌入的致命問題

傳統方法（如 TransE）把每個實體表示成空間中的一個點。兩個節點的相關性 = 它們的向量距離。

在法律推論中，這有一個根本缺陷：

幾何擁擠與特徵坍縮問題

一條法規可能適用於數百種不同的職災事件（比如「高處作業」法規適用於各種墜落事件）。如果每個職災事件都是一個「點」，而它們都必須靠近同一個法規「點」，那麼這幾百個職災的點就會擠在一個法規點旁邊，形成一團混亂的幾何擁擠（geometric crowding）。節點特徵彼此覆蓋，最終坍縮成無法區分的一坨，失去個別語意。

BoxE 的解法：把實體表示成「盒子」

BoxE 的核心洞察：法律規範不是一個「點」，而是一個「空間區域」——它定義了一組行為規範的邊界，只有滿足特定要件的事件才會落入其範圍內。

圖2：傳統點嵌入 vs. BoxE 盒子嵌入。左側：多個職災事件擠在法規點旁，特徵坍縮無法區分。右側：法規是大盒子，職災事件是小盒子；若小盒子落在大盒子內（相交體積 > 0），則代表該事件涉及此法規。

在 BoxE 中，每個實體被建模為一個 d 維超矩形（hyperrectangle），由兩個向量決定：

BoxE Box(entity) = (C, W)
其中：
C = 幾何中心向量 (center) ∈ ℝ^d
W = 幾何寬度向量 (half-width) ∈ ℝ^d (每個維度都非負)

這個盒子在第 i 維的範圍是：[C_i - W_i, C_i + W_i]

法規 r 的盒子 Box(r) 代表「涵蓋某類違規行為的語意空間」；職災事件 c 的盒子 Box(c) 代表「此事故的特徵區間」。如果兩個盒子有充分的相交體積（intersection volume），就代表這個職災事件真的落在法規的管轄範圍內。

法律「涵攝」的幾何化

法律推論中有一個核心概念叫「涵攝（subsumption）」——判斷一個具體事實是否落入某條法律條文的構成要件之中。BoxE 把這個抽象的法律邏輯，轉化成了具體的幾何相交體積計算，讓電腦可以精確計算。

Section 05

方法一：動態細粒度異質圖譜張量化

在建立了知識圖譜和了解 RGAT/BoxE 之後，研究者面臨第一個工程問題：如何讓 RGAT 既能處理「多種關係」，又不損失節點的精細語意？

從矩陣到張量

傳統圖用鄰接矩陣 A[i][j] = 1 表示「節點 i 和 j 之間有邊」。但這個矩陣無法記錄邊的種類。

矩陣 vs. 張量的類比

鄰接矩陣就像一張「認識與否」的關係表（二維）。張量（Tensor）就是在這張表上多加一個維度：A[i][j][k] = 1 表示「節點 i 和 j 之間有第 k 種關係的邊」。三維張量就像是「針對每種關係分別建一張關係表，疊在一起」。

3D Tensor G = (V, E, R)
A ∈ ℝ^{|V| × |V| × |R|}

A[i][j][k] = 1  ← 節點 i 到 j 之間存在第 k 種關係

如：A[墜落事件_A][失足踩空][HAS_CAUSE] = 1
A[失足踩空][未設安全網違規][LEADS_TO] = 1

法理階層殘差連接：防止特徵平滑

深層 GNN 有一個著名的工程風險叫特徵平滑（Feature Smoothing）：在多層訊息傳遞後，每個節點都聚合了越來越大範圍的鄰居資訊，導致所有節點的向量趨於同質化——「墜落事件」和「高處作業法規」的向量變得越來越像，失去了各自的獨特語意。

類比：走廊的八卦

如果你把一個消息傳給10個人，再讓每個人把聽到的消息平均整合後傳出去，傳個3輪之後，所有人持有的「平均消息」會越來越趨同。這就是特徵平滑。

解法是殘差連接（Residual Connection）——你可能在 ResNet 課程中接觸過這個概念：在每層更新後，強制加回節點的原始特徵，確保「自己的根本身份」不被鄰居資訊淹沒：

RGAT + Residual h_i^(l+1) = σ(Σ_r Σ_{j∈N_i^r} α_ij^r · W_r · h_j^(l))
+ β · H_hier(i) ← 法規階層先驗向量（條、款、項的位階）
+ γ · h_i^(0) ← 初始原子特徵的直接捷徑（抵抗被稀釋）

其中 H_hier(i) 是一個先驗向量，編碼了這個節點在法律體系中的「位階」（是法條本體？是條文下的某款？），強制模型在每層更新後都能重新錨定節點的法律地位，不至於把「第3條第2項第1款」和「第18條本文」混為一談。

RGAT 的輸出到 BoxE 的銜接

RGAT 最後一層的隱藏狀態 h_i^(L) 被兩個獨立的線性映射層轉換，分別生成 BoxE 所需的中心向量和寬度向量：

Feature Decoupling C_i = W_center · h_i^(L) + b_center ← 盒子中心
W_i = Softplus(W_width · h_i^(L) + b_width) ← 盒子寬度（非負）

這裡用 Softplus（一種平滑版的 ReLU）取代普通的線性映射，目的是確保寬度向量的每一維都是非負的——因為盒子的「寬度」不可能是負數。

Section 06

方法二：基於幾何相交體積的約束子圖採樣

有了每個節點的 BoxE 表示之後，下一步是：從整張圖中挑出與當前職災事件高度相關的子圖（subgraph），作為送給 LLM 的證據。

為什麼不用向量距離？

傳統 RAG 的做法是計算查詢向量與資料庫中每個節點向量的距離，取最近的 K 個。這個方法對於法律推論有根本缺陷：

方法 原理 問題
向量距離（傳統 RAG） 找「語意上最接近」的法規 「接近」≠「涵攝」。兩個語意相近的法條不一定互相適用。
幾何相交體積（本研究） 看職災事件的盒子是否落入法規的盒子內 真正實現「法律涵攝」的幾何化表達，數學嚴格。

相交體積的計算

兩個 d 維盒子 Box(c)（職災事件）和 Box(r)（法規）的相交體積，就是每一維上「重疊長度」的連乘積：

Intersection Volume Volume_inter(c, r) = Π_{i=1}^{d} max(0,                  ← 連乘積（每維重疊量）
                          min(C_c,i+W_c,i, C_r,i+W_r,i) ← 兩盒子右界的較小值
                          -max(C_c,i-W_c,i, C_r,i-W_r,i)) ← 兩盒子左界的較大值

直觀理解：在一維情況下，如果兩條線段 [2, 5] 和 [3, 7] 有交集，交集長度 = min(5,7) - max(2,3) = 5 - 3 = 2。擴展到 d 維，就是每維交集長度的乘積。

數值穩定化：從連乘到連加

工程陷阱：維度坍縮（Dimension Collapse）

當 d = 256 時，如果有任意一個維度的重疊量為 0（哪怕只有 0.000001），整個連乘積就變成 0！這代表模型完全喪失了從這個子圖學習的機會，反向傳播時梯度消失，訓練失效。

解法：對數空間轉換。利用 log(a·b·c) = log(a) + log(b) + log(c)，把容易崩潰的連乘積轉成穩定的連加，並加上平滑因子 ε 防止 log(0)：

Log-Volume (Stable) logVolume~_inter(c, r) = Σ_{i=1}^{d} log(max(0, overlap_i) + ε)

連乘 → 連加：數值穩定，梯度不消失
+ ε（小正數）：防止 log(0) 的數值錯誤

動態子圖切片

有了對數相交體積之後，研究者設定一個動態閾值 θ，建立一個布林遮罩矩陣 M，只保留「相交體積夠大」的節點連結：

Subgraph Masking M[i][j] = 1 ← 若 logVolume~_inter(i, j) > θ
M[i][j] = 0 ← 否則（此連結在法律上不構成涵攝）

G_sub = A ⊙ M ← 張量 A 和遮罩矩陣的元素乘積 → 高置信度推論子圖

這樣我們就從整張職安知識圖譜中，精確切出了一個高置信度推論子圖 G_sub，只包含在幾何上與當前職災事件有法理涵攝關係的節點和邊。

Section 07

方法三：拓樸同構之圖譜序列化提示生成

現在我們有了高置信度子圖 G_sub，但遇到一個核心的跨模態（Cross-modal）挑戰：這個子圖是以 256 維的連續幾何向量形式存在的，而 LLM 只能閱讀自然語言文字。

解析度類比

子圖是 144p 的幾何資訊，LLM 是 1080p 的語言理解機器。如果直接把向量硬塞進 LLM（用線性投影層做維度轉換 256 → 4096），資訊會嚴重失真——就像把一張 144p 影像硬拉成 1080p，只是在放大像素格，並沒有增加真實資訊。

本研究的解法是Graph Prompting：設計一個映射函數 φ，把幾何子圖轉換成結構化的自然語言序列，同時保留圖結構的拓樸資訊（即節點與邊的連接方式不變）。

挑戰：無序走訪導致的雜訊

最直覺的做法是隨機遊走（random walk）子圖，把走過的路徑翻譯成文字。但這會引發另一個問題：

  • 子圖中可能有迴圈（cycle），隨機遊走會反覆走過相同的節點，產生大量冗餘文字。
  • 冗餘文字會把 LLM 的自注意力機制「稀釋」掉，讓模型無法聚焦在真正重要的法律推論鏈上。
  • 如果子圖夠大，冗餘文字甚至會溢出 LLM 的上下文視窗（Context Window Overflow），強制截斷。

解法：法理資訊熵導向的 Beam Search

研究者把子圖序列化重構成一個路徑最佳化問題。對子圖中的每一條潛在推論路徑 P = (v1, r1, v2, …, rk-1, vk)，計算一個法理資訊熵分數 S(P)：

Path Score S(P) = Σ_{t=1}^{|P|-1} Softmax(W_r^t) · logVolume~_inter(v_t, v_{t+1})

↑ ↑
RGAT 學到的關係重要性 BoxE 計算出的法理涵攝強度

這個分數越高，代表這條路徑中每一步的「關係重要性」和「法律涵攝強度」都越大，是最有代表性的推論路徑。

然後使用Beam Search（一種保留 Top-K 候選的啟發式搜尋演算法）從子圖中抽取 Top-K 條最佳路徑，確保這些路徑是有向無環的（DAG），不含冗餘迴圈。

Beam Search 類比

想像你在一棵決策樹上找最佳路徑。Beam Search 不是全部展開（太慢），也不是每步只留最好的一條（貪心、容易錯過好路徑）。它每步保留最好的 K 條候選，像是同時維護 K 個「探索隊伍」，最終取最優解。

翻譯成自然語言

最佳路徑按照「事實認定 → 違法判斷 → 法規適用」的法理三段論結構，翻譯為三元組序列：

Graph → Prompt 職災事件 → [導致] → 違規項目 → [違反] → 法規名稱

例：
作業員踩空事件 → [導致] → 高處作業無防護裝置 → [違反] → 職安法第18條第2項

這樣就把原本隱性的 256 維 BoxE 幾何向量，精煉轉化為 LLM 可以直接讀取的顯性上下文約束，完全消除了跨模態適配器的失真問題，同時確保送給 LLM 的文字具備嚴格的法理因果結構。

Section 08

方法四：幾何空間引導思維鏈（Geo-CoT）

有了結構化的提示詞 T_prompt 之後，LLM 就可以開始生成法律推論。但一般的思維鏈（Chain-of-Thought, CoT）讓模型自由發散，在法律推論中極易發生「語意漂移」——模型可能半途跳到它在預訓練中見過的常見說法，而非嚴格依照子圖的法律邏輯推理。

法律三段論的強制結構

Geo-CoT 的核心：把古典邏輯的法律三段論（syllogism）映射為嚴格的自迴歸解碼約束，強制 LLM 的生成序列 Y 解耦成三個依序依賴的子序列：

圖3：Geo-CoT 三段推理架構。強制 LLM 依序完成三個推理階段，每一步都必須錨定在幾何子圖的約束中。

在數學上，這相當於把全局條件機率 P(Y|X) 分解為受限的階段性邊際機率連乘：

Conditional Decomposition P(Y_law | X_event) = Π_{k∈{fact,bound,rule}} Π_{t=1}^{|Y_k|}
                      P(y_{k,t} | y_{k,<t}, Y_{<k}, X_event, φ(G_sub))

意義：第 k 階段第 t 步的輸出，必須同時以：
- 當前階段前面的輸出（y_{k,<t}）
- 前一階段的完整輸出（Y_{<k}）
- 原始事件描述（X_event）
- 幾何子圖轉換的提示（φ(G_sub}）  ← 最關鍵的約束
為條件——不得跳步。
Geo-CoT 的精妙之處

一般 CoT 只是告訴 LLM「請逐步推理」，但推理的每一步去哪個方向完全由模型的先驗自由決定。Geo-CoT 則是在每一步都提供了幾何錨點：模型在做邊界測試（Y_bound）時，必須以自然語言重現 logVolume~_inter(c, r) 的邏輯——也就是說，它必須論述「為什麼這個事件的特徵確實落在這條法規的構成要件空間內」，而不是在憑感覺說話。

Section 09

方法五：解碼層幾何懲罰機制

這是整套系統的最後一道防線，也是最直接的工程手段——直接干預 LLM 的輸出層。

LLM 解碼的基本原理

你需要知道 LLM 是如何生成文字的：

  1. 模型在每一步 t 對整個詞彙表 V 中的每個 token，計算一個原始分數（Logit），得到向量 z_t ∈ ℝ^|V|。
  2. 對 z_t 做 Softmax 轉換，得到每個 token 的輸出機率 P(y_t = i)。
  3. 從這個機率分布中採樣（或取最大值），決定下一個輸出的 token。

問題：即使經過 Geo-CoT 的引導，LLM 在最終輸出具體法條名稱時，仍可能受到預訓練先驗的影響，對高頻的「安全牌」法條給出高 Logit，而輸出錯誤的法規。

幾何懲罰項的設計

本研究設計了一套「詞表—圖譜實體映射矩陣」，把每個法規名稱對應到詞彙表中的 token，然後動態計算懲罰項 Π：

Penalty Term Π_i =
  logVolume~_inter(c, r_i) ← 若 token i 指向法規 r_i，且 r_i ∈ G_sub（幾何上有涵攝）
  -∞                      ← 若 token i 指向法規 r_i，但 r_i ∉ G_sub（無法理涵攝關係）
  0                      ← 非法規 token（如「的」、「第」…等語法詞彙）

然後將懲罰項加回原始 Logit，修正後的 Logit 為：

Adjusted Logit z̃_{t,i} = z_{t,i} + α · Π_i

P(y_t = i | y_{<t}, X) = exp(z̃_{t,i}) / Σ_j exp(z̃_{t,j})
-∞ 懲罰的法學意義

對一個法規 token 施加 -∞ 的懲罰，等同於在法學邏輯上行使「絕對否決權」。它的輸出機率直接變成 exp(-∞) = 0，讓模型在物理上不可能輸出這個法條——因為在幾何空間中，這條法規和當前職災事件根本沒有涵攝關係，所以就算模型再怎麼「想說」，也被封殺了。

為何只懲罰法規 token，不動語法詞彙？

懲罰機制僅針對映射到法規實體的 token 集合 V_law ⊂ V 做選擇性懲罰，而不影響「第」、「條」、「規定」等語法詞彙。這樣做是為了不干擾 LLM 生成流暢句子的能力，只在「哪條法律」這個關鍵選擇上施加幾何約束。

在 Hit@1 指標上，本研究的 RGAT+BoxE 達到 95.92%，相比 RGAT+RotatE 的 74.73% 提升了 21.19 個百分點——在一個模型直接「猜對」的任務上，這是非常顯著的進步。

為什麼 BoxE 遠勝 RotatE？

RotatE 同樣是知識圖譜嵌入方法，但它把關係建模為旋轉操作（點對點）。在多對多的法律涵攝關係中（一條法規適用於多種職災），旋轉嵌入同樣面臨幾何擁擠問題。BoxE 的盒子設計天然支援「一對多涵攝」，每個職災事件的小盒子都可以落在同一個法規大盒子內，互不干擾，從而有效解決了特徵坍縮問題。

研究的理論貢獻總結

五層幾何約束的設計邏輯

這個研究的獨特性在於：它從資料表示到模型輸出的每一個環節，都引入了幾何約束——張量化圖譜（保留關係種類）→ 殘差連接（保留法律位階）→ BoxE 相交體積（實現法律涵攝）→ Graph Prompting（保留拓樸資訊）→ Geo-CoT（強制三段論）→ 解碼懲罰（封殺無效法條）。這種端到端的幾何約束設計，讓整套系統在任何一個環節都難以滑入「頻率偏差」的陷阱。
